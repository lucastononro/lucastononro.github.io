The problem with a coding agent that works for eleven minutes is that you do not sit and watch it for eleven minutes. You go and do something else, and then either you come back too early and hover, or too late and the thing has been sitting there for six minutes waiting for you to answer a yes/no question.

Every product answer to this involves a push service, an API key, a webhook, and a phone. [`notify`](https://github.com/lucastononro/notify) is the unglamorous answer: your computer already knows how to make a noise and how to talk. Use that.

- 🔔 `play_sound` — a system ping. "Glance at the screen."
- 🗣️ `notify` — a sound, then a spoken sentence or two, in a decent local voice.

No API key, no network, no rate limit, no telemetry. On macOS it is `afplay` and `say`, both of which shipped with the machine.

## The part that took the thinking

Not the audio. The audio is twenty lines. The hard part is that **a message that reads fine is often unlistenable.**

An agent's natural output is markdown: bullet points, file paths, a table, a code span. Feed that to a speech synthesiser and you get a robot reciting `src/lib/handlers/inbox_service.py` character by character while you stand in the kitchen holding a mug. So the skill constrains what the model is allowed to say out loud. Plain sentences. No paths, no tables, no code, no markdown. The detailed version stays in the chat where you can read it; the spoken version is what a colleague would have shouted down the hallway.

The other half of that is **beats**. A single long sentence read at a constant clip is hard to parse from another room, so the tool takes a list of short beats with pauses between them:

```python
notify(beats=[
    {"text": "Build done.", "pause_after": 0.4},
    {"text": "Two tests failed in the billing module."},
])
```

One to three beats is normal; more than three and you are giving a speech.[^beats] Each `pause_after` is clamped, so no beat can hold the microphone hostage.

[^beats]: Which is also, roughly, the rule for leaving a voicemail — headline first, then the one detail that changes what the listener does next.

## Picking a voice that does not sound like 1998

macOS ships a range of voices whose quality varies enormously, and which ones are installed differs per machine. So the server walks a preference ladder and takes the best thing actually present:

```python
VOICE_PRIORITY = [
    "Ava (Premium)",
    "Zoe (Premium)",
    "Evan (Premium)",
    "Allison (Premium)",
    "Tom (Premium)",
    "Samantha (Enhanced)",
    "Daniel (Enhanced)",
    "Samantha",
]
```

Same idea for sounds. The public names — `hero`, `glass`, `sosumi`, `basso`, `funk`, `ping`, `tink`, `submarine`, and friends — are platform-agnostic. On macOS each maps to a file in `/System/Library/Sounds`; on other platforms each name carries a semantic *category* that resolves to the nearest local equivalent. You ask for `glass` and you get something glassy, wherever you are.

Every backend call is guarded. A missing voice, a missing sound file, an absent player — each returns a descriptive string instead of raising. An attention tool that crashes the MCP server is worse than no attention tool, because now the agent is stuck *and* silent.

## One server, two agents, zero paths

The bit I am quietly pleased about is distribution. The same skill and the same MCP server serve both Claude Code and Codex, and neither one references a bundled script path. The server is published as a `uvx`-runnable package, so both agents register it with an identical, path-free command:

```bash
uvx --from "git+https://github.com/lucastononro/notify#subdirectory=mcp-server" notify-mcp
```

`uvx` builds and caches the package (and its single dependency) from git on first run. No venv to manage, no per-harness path substitution, no "works on my machine because the plugin happens to live there."

```
/plugin marketplace add lucastononro/notify
/plugin install notify@notify-marketplace
```

Then: *"ping me when the tests pass."*

## Honest status

macOS is tested. Windows and Linux are best-effort and untested — PowerShell `System.Speech` and `winsound` on one, `spd-say`/`espeak` plus `canberra-gtk-play`/`paplay` on the other. The whole platform layer is one file, `mcp-server/notify_mcp/server.py`, so if it is wrong on your OS it is wrong in an obvious and fixable place.

Unexpected side effect: I now leave the room *deliberately*. Knowing the agent will come and find me changed how I use it — fewer check-ins, longer tasks, less hovering. The tool is thirty lines of audio plumbing and it changed my working rhythm more than anything else I built this year.
