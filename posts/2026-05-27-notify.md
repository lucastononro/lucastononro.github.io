The problem with an agent that works for eleven minutes is that you don't watch it for eleven minutes. You leave, and then you either come back too early and hover, or too late and it's been waiting six minutes for a yes/no.

Every product answer involves a push service, an API key and a phone. [notify](https://github.com/lucastononro/notify) is the unglamorous one: `afplay` and `say` shipped with the machine. No key, no network, no telemetry.

## The hard part isn't audio

Audio is twenty lines. The hard part is that a message which *reads* fine is often unlistenable. Feed an agent's markdown to a speech synthesiser and you get a robot reciting `src/lib/handlers/inbox_service.py` while you stand there holding a mug.

So the skill constrains what may be said out loud: plain sentences, no paths, no tables, no code. The detail stays in the chat. And it speaks in **beats**, not paragraphs:

```python
notify(beats=[
    {"text": "Build done.", "pause_after": 0.4},
    {"text": "Two tests failed in billing."},
])
```

One to three beats. More than three and you're giving a speech.

## Fourteen sounds, six meanings

Sound names are platform-agnostic and each carries a semantic category, so a Linux box can resolve the nearest local equivalent instead of failing:

```
hero → success    sosumi → blocked    basso → error
funk → warning    ping   → fyi        submarine → attention
```

`sosumi` means *blocked* — that's the one you want when the agent needs a decision, and it feels genuinely different from something breaking.[^guard]

[^guard]: Every backend call is guarded. A missing voice returns a descriptive string rather than raising, because an attention tool that crashes leaves the agent stuck *and* silent.

macOS is tested. Windows and Linux are best-effort, and the whole platform layer is one file, so when it's wrong it's wrong somewhere obvious.
